# Task 5 — Traceability, Verification and RTM

## Traceability Chain

A stakeholder need flows through requirements, system elements, source code,
and verification records. The chain is computed from Git — never hand-typed.

## @relation Tags in Source Code

src/auth.py tags functions with the requirement UIDs they implement:

- login — implements REQ-001
- enforce_session_timeout — implements REQ-002
- reset_password — implements REQ-001 and REQ-003

## Verification Records

Verification rows live in the Baserow Verification table with fields:
Method, Acceptance Criteria, Result, and a link back to the Requirement.

- VER-001 (Test, Pass) verifies REQ-001
- VER-002 (Test, Pending) verifies REQ-002

## RTM

Generated by rtm.py. One row per requirement. Columns: UID, Title,
Statement, Status, Parent Need, Code Link.

Outputs: rtm.csv, rtm.html, coverage.txt.

## Sequence Diagram

The RTM generation sequence is shown in this repository as Mermaid source.
See SUBMISSION.md for the rendered diagram.

Sequence:
  Developer -> Git: commit .sdoc + relation tags
  Developer -> rtm.py: run python3 rtm.py
  rtm.py -> Git: read docs/generated/*.sdoc
  rtm.py -> Git: read src/**/*.py
  rtm.py -> rtm.py: parse UIDs, parents, code links
  rtm.py -> rtm.csv: write RTM + coverage
  Developer -> rtm.html: open in browser
